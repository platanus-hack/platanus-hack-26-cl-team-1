# Bomberos Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fire companies with editable trucks per type, automatic dispatch over streets cut by fire and by
historical cuts, and their effect on the fire (defended cells) and the evacuation (rescues), off by default.

**Architecture:** Two passes (spec approach A). The worker runs the fire without firefighters, derives street
closure times, plans every unit with `planBrigades` (routing + greedy sector dispatch + water windows → a
per-cell `FireDefense`), reruns the fire with `defense`, runs the evacuation on it and applies rescues.

**Tech Stack:** TypeScript, Vite, React, MapLibre GL, vitest; data hand-curated JSON.

**Spec:** `docs/superpowers/specs/2026-11-22-bomberos-design.md`

## Global Constraints

- On `main` by 2026-11-22 05:30 America/Santiago; one PR, conventional title, CI Lint + Test green.
- UI copy in Spanish; code, identifiers, docs in English. No game language.
- Contract changes in `web/src/engine/types.ts` land with every consumer in the same PR.
- Every number either cites a source or is labelled "supuesto" in code and UI.
- Bomberos off by default: with it off, outputs are bit-for-bit what they are today.
- Never fail silently: malformed `brigades.json` throws a `DataError` naming the file.

## Review Focus

- Bomberos on with every count at 0 → the fire and evacuation equal the "off" run exactly (test in Task 3).
- A unit whose station node has no open route anywhere → listed "sin acceso", never silently dropped (Task 2).
- Ruta 68 cut toggled off → reinforcements route through it (Task 2 test).
- Station outside the grid or unknown unit key in `brigades.json` → `DataError` (Task 1 test).
- Cell defended but fire arrives after the window → it burns normally (Task 3 test).

### Task 2: Brigade engine (routing, dispatch, defence field, rescue)

**Files:**
- Create: `web/src/engine/brigade/model.ts` (`FIREFIGHT_MODEL`: tankL `[3000,1500,8000,0]`, flowLPerMin 200, bombaRadiusM 60, forestalRadiusM 120, directAttackMaxKwM 1730, grassLoadTHa 4.5, heatKJPerKg 18000, rescuePerHour 6, rescueRadiusM 300, sectorCells 8; each with source/supuesto comment)

- Modify: `web/src/engine/evac/simulate.ts` (export `dilateMin3x3`)
- Test: `web/src/engine/brigade/brigade.test.ts`

**Interfaces:**
- Consumes: `Prepared` (`asPrepared`), `BrigadesFile`, `FireResult.arrivalMin`, `EvacParams.safetyMarginMin`, `carKmhByClass`.
- Produces:
  - `edgeClosuresFromFire(prep, arrivalMin, marginMin): Float32Array`
  - `earliestArrival(prep, originNode, departMin, closesMin: Float32Array, cutEdges: CutWindow[]): Float64Array` (per node; Infinity unreachable) plus predecessor edges.
  - `planBrigades(input: BrigadeInput): BrigadePlan` with
    `BrigadeInput { prep, grid, fuel, arrivalMin, settings: BrigadeSettings, file: BrigadesFile, t0, marginMin, carKmhByClass }`,
    `BrigadeSettings { units: Record<string, number[]>, dispatchMin: Record<string, number>, reinforcementUnits: Record<string, number[]>, reinforcementMin: Record<string, number>, historicalCuts: boolean }`,
    `BrigadePlan { defense: FireDefense; units: PlannedUnit[]; cutEdges: number[] }`,
    `PlannedUnit { origin: string; type: UnitType; departMin; status: 'deployed' | 'no_access'; siteNode: number; arriveMin; untilMin; path: number[] /* edge ids */ }`.
  - `applyRescue(prep, evac: EvacResult, plan: BrigadePlan, horizonMin): { householdRisk: Float32Array; householdStatus: Uint8Array; rescuedHouseholds: number; expectedTrappedHouseholds: number }`.

- [ ] Step 1: tests on a small synthetic graph/grid:
  `routes around an edge the fire closes before the truck gets there`, `waits are not allowed: arrival Infinity when the only edge closes first`,
  `a historical cut blocks only inside its window`, `Ruta 68 toggle off lets the reinforcement through`,
  `unit with no reachable sector is no_access`, `two Bomba units prefer two different sectors of equal value`,
  `aljibe at the same site extends the window by 8000/(200·n) min`, `Forestal sets maxKwM 1730 on wildland cells only`,
  `rescue sets risk 0 for at most 6·hours households within 300 m, highest risk first`.
- [ ] Step 2: run → fail.
- [ ] Step 3: implement. Routing: binary-heap Dijkstra on node arrival time; an edge is usable if `t < closes(e)` and `t` is outside every active cut window on it; travel = len / speed(cls); PATH excluded. Sectors: 8×8 cell blocks with buildings reached by pass-1 fire; value(t) = buildings in the block with cell arrival > t; site = block's node nearest its threatened buildings' centroid. Greedy: all units sorted by departMin (stable: file order); one Dijkstra per (origin, departMin) cached; pick max value(arrive)/(1+same-type units already there) among blocks with value > 0; ties → earliest arrive. Window: water at site = Σ tanks of units there; until = arrive + water / (flow · water-using units there). Defence: Bomba → URBAN_LOW/URBAN_DENSE cells within 60 m of site cell, maxKwM Infinity; Forestal → GRASS/SHRUB/FOREST/CROP within 120 m, maxKwM 1730; overlapping windows merge as min(from), max(until).
- [ ] Step 4: tests pass. Commit `feat(brigade): routing, dispatch and defence field`.
